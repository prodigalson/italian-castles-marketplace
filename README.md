# Italian Castles Marketplace

A Vite static marketplace MVP for Italian castles and Puglia masserias for sale. The current inventory is a compliant manual/link-only fixture: source links, source status, last-checked times, provenance, and inquiry actions are preserved, while unavailable or permission-gated sources are represented transparently instead of scraped.

## Local Setup

Requirements:

- Node.js 20 or newer.
- npm.

Install dependencies:

```bash
npm install
```

Run the local app:

```bash
npm run dev
```

Build the deployable static site:

```bash
npm run build
```

Preview the built site locally:

```bash
npm run preview
```

## Data Refresh

The castle and masseria inventory is generated by `scripts/refresh-castle-inventory.mjs`.

```bash
npm run inventory:refresh
```

The refresh writes:

- `data/castle-listings.json` for canonical marketplace listings across `asset_class` values.
- `data/castle-source-status.json` for source-level compliance, inventory scope, and availability status.

The current adapter is intentionally manual and link-only. It includes a committed JamesEdition Italy-castle category-card snapshot at `data/manual-review/jamesedition/castle-card-snapshot.json` and a property-level Puglia masseria review at `data/manual-review/jamesedition/masseria-property-url-review.json`; only rows with stable original property-listing URLs are displayed. This preserves more than 100 active castle listings after dedupe plus two active masserias while avoiding copied source photos, long descriptions, hidden contact data, broad landing/category links, or blocked endpoints. Before adding an automated adapter, update `docs/castle-data-foundation.md` with dated robots and terms evidence, confirm the exact paths/endpoints are permitted, and preserve attribution, license basis, last-checked time, source status, inventory family, and inquiry route in every emitted record.

## Deployment

This repo is configured for Vercel via `vercel.json`.

Deployment build command:

```bash
npm run build
```

Static output directory:

```text
dist
```

The build runs `vite build` and emits the static app to `dist`.

## Launch Checks

Launch-readiness evidence is tracked in `docs/launch-readiness.md`. Before launch, rerun:

```bash
npm run inventory:refresh
npm run qa:launch
npm run build
```

Then verify the built app in desktop and mobile widths, including:

- Cover page, enter flow, listing navigation, gallery thumbs, filters, sharing fallback, and source links.
- Source attribution, stale/removed labels, last-checked time, provenance text, and inquiry actions.
- SEO metadata, canonical URL, Open Graph/Twitter preview tags, `robots.txt`, and structured data.
- Keyboard navigation, focus states, form labels, responsive layout, and reduced-motion behavior.

## Property Image Policy

An image may be presented as the listed property only when its record identifies it as `actual_property` and documents partner, source, or owned display rights. The current link-only inventory does not have those permissions, so every listing uses owned local editorial artwork instead of copied or hotlinked listing photos. Each substitute is visibly labelled exactly `Editorial placeholder images.` and records its credit, rights basis, and rights note.

The marketplace hero is a locally served 3840×2560 photograph of Rocca Calascio by Marcotigretti, licensed under CC BY-SA 4.0. Its source page, download URL, source and delivered dimensions, hash, attribution, license, display treatment, and non-listing status are recorded in `data/site-image-assets.json` and linked visibly on the cover. The social preview remains owned editorial artwork. When intentionally changing the social artwork, run `npm run assets:generate`, visually review the 1200×630 PNG, update its recorded hash, and commit the PNG. Production builds never regenerate it: Vite copies the committed bytes, then `npm run qa:dist` verifies that `dist/og/cover.png` is byte-for-byte identical. `npm run qa:launch` separately validates listing and site-image provenance, visible labelling, local asset paths, source hashes, dimensions, and the committed preview hash.
